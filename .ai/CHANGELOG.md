## 2026-10-03 — Installed PWA updates itself on every deploy

- **Gap found.** A plain deploy changed the pages but not `internal-sw.js`, so an installed copy never got a signal that a new version shipped: a long-resident app kept old page code, and the saved pages/assets stayed old until the 6 h refresh.
- **Fix.** One build id per build (`astro.config.mjs`, from git: the first attempt used the clock and the pages and worker came out 2 ms apart, because Astro evaluates the config twice per build; caught by comparing `dist` before committing) is stamped into the worker file and every internal page. The worker changes on every deploy, so the browser installs it by itself; the app also checks when it is brought to the front, when the connection returns, and every 30 min. A page older than its worker reloads itself when that is safe (visible and clean, or on next open), otherwise offers a Reload banner. Saved pages and assets refresh at once after a deploy. Tools shows the running version and has Check for updates. Details: `.ai/references/internal-pwa.md`, "How installed copies update".
- **Second bug, found by the browser run.** Warm-up success was recorded by the page that asked for it, but this is a multi-page app: the page is usually gone before a 10 s run finishes, so success was never recorded and the retry back-off then blocked every later page. Warm-up state (last clean build/time, last unfinished attempt, running) now lives in the worker (`cv-meta-v1`, no customer data) and survives page changes; a deploy always gets its refresh.
- **Verification.** `npm run test:internal-pwa` (build id stamped identically into worker and every page, update decisions, warm state in the worker). Chromium against the Pages emulator with a simulated deploy while the app was open: an idle Today reloaded itself onto the new build and the saved pages refreshed to it; with half-typed text in the quote form a second deploy left the text alone and showed the Reload banner; Reload and Check for updates behaved. ## 2026-10-03 — Command Center bug sweep (found by running the real handlers and pages, not by reading)

Method: the built UI served over the real `/internal/api` handlers on a seeded SQLite database, driven in Chromium at 320 and 375 px (a throwaway harness, not committed). Every page loaded with no JavaScript errors; the bugs below were the real finds.

- **Quote builder: editing a line's quantity or price was impossible.** Every keystroke rebuilt all rows, replacing the field being typed in, so focus dropped after one character (typing "1234" left "0"). Rows now rebuild only on add/remove/load; typing refreshes totals in place (`updateTotals`).
- **Quote builder on a phone:** the fieldsets grew to the widest child (page 9 to 69 px too wide at 375/320 px) and the line-items table squeezed the description to about five characters. `.qb-block` can shrink, the choice rows wrap, and below 700 px each line is a card.
- **Signature pad on Mark's device overflowed every phone** (fixed 600 px canvas, no CSS: the document was 644 px wide at 375 px and 40% of the pad was off-screen) and used raw pixel positions. It now scales to the card and converts pointer positions to the 600x180 pad like the customer page, drops points that barely moved, and clamps to the pad.
- **Signature storage:** the device used to send finished SVG that the server stored after cutting it at 20,000 characters (a long signature was truncated mid-tag) and rendered with `innerHTML`. The device now sends strokes and `PATCH /internal/api/quotes/[id]` renders them with `renderSignatureSvg`, the same validated path as the customer link (60 strokes, 4,000 points, inside the pad). A raw `signatureSvg` is no longer accepted.
- **Money was rounded to whole dollars everywhere,** while quotes, discounts, General jobs and payments work in cents. The emailed invoice showed a $1,234.50 subtotal as "$1,235" and a $0.50 discount as "-$1"; Payments showed a $4,800.50 job as "$4,801"; the builder's totals rounded. New `formatCents` (`src/lib/money.ts` and a hand-kept copy `functions/internal/_lib/money.mjs`): whole dollars stay "$1,234", anything with cents shows both digits. Used by the invoice email, quote follow-up reminders, the payment-limit error and every Command Center list/detail page. Headline totals (dashboard cards, Analytics) stay whole-dollar on purpose. The invoice "Issued" date now uses Pacific time.
- **Dashboard "cities":** leads with a NULL city and with an empty city produced two rows both labelled "City not provided" (SQLite grouped on the raw column). It now groups on the displayed value, so NULL, empty and stray spacing/case ("camas", " Camas ") are one row.
- **Deleting a draft quote** left its customer signing links (live for 30 days) and automatic follow-up reminders behind. Both are deleted with the quote.
